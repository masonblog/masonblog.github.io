# 策划《议正言辞》播客选题

## 遵守项目约定

先阅读仓库根目录的 `AGENTS.md`、`README.md`、`config.yml`，再运行 `git status --short`。保留用户未提交的改动。

本技能只做选题策划，不修改节目文稿、播客页、封面及其他站点内容。可维护本技能自己的派生覆盖索引 `references/episode-coverage.json`；只有完整阅读对应版本的源文字稿后才能更新索引。发布单集时改用 `publish-podcast-episode` 技能。

## 增量盘点既有内容

先运行：

```powershell
python .agents/skills/select-podcast-topic/scripts/check_episode_index.py --pretty
```

脚本只解析 front matter、文件哈希和播客页链接，不把文字稿正文送入上下文。按输出状态处理：

1. `missing`、`changed` 或 `incomplete`：读取 `references/episode-index-schema.md`，逐篇完整阅读这些源文字稿，再新增或重写对应索引条目。**不得只根据标题、简介、目录或旧摘要更新哈希。**
2. 索引缺失、schema 失效或 `audit.due: true`：完整阅读全部中文源文字稿，重建或审计索引。全量审计至少每新增 5 集或每 180 天进行一次。
3. `orphaned`、`podcast_page_only` 或 `duplicate_episodes`：核对文件改名、删除、期数冲突、front matter 和播客页差异；不擅自删除内容或索引记录，期数仍有歧义时请用户确认。
4. 全部为 `current` 且审计未到期：直接读取紧凑覆盖索引，不再完整重读所有历史文字稿。

索引必须覆盖：期数、发布状态、年代、法域、案件或人物、法律部门、制度机制、核心问题、主要结论、叙事钩子、主要史料类型、与当下的连接点和易重复之处。排除 `.en.md`，避免把译文当成另一集。将 `draft: false` 且未设 `hidden: true` 的内容标为“已发布”；其他带有 `podcast:` 字段的中文内容标为“已规划”，同样排除出候选题。

索引更新后再次运行检查脚本。只有文件哈希和必填语义字段都通过检查，才把条目视为可复用。覆盖索引是导航和检索层，不是原文证据；发现摘要与原文冲突时以原文为准并修正索引。

形成候选池后，根据核心问题、制度机制、人物案件、史料和预期结论，从索引中找出与领先候选最相似的 2 至 4 集并完整回读。若回读发现新的重叠或索引不足，扩大回读范围。最终去重不得仅依赖摘要或关键词。

需要确认“已发布”边界或发现本地落后于公开平台时，核对小宇宙主 RSS 和节目页；当前核对入口以 `publish-podcast-episode` 技能所列来源为准。若平台、本地播客页和文字稿互相冲突，说明差异，不要擅自删改内容。以已发布和已规划内容中的最高期数加一得到下一期编号，并使用两位数字；编号仍有歧义时先请用户确认。

## 读取小宇宙官方往期表现

从仓库根目录运行：

```powershell
python .agents/skills/select-podcast-topic/scripts/fetch_xiaoyuzhou_metrics.py
```

脚本先读取《议正言辞》的小宇宙官方节目链接，再汇总 `content/podcast.md` 中的全部小宇宙官方单集链接，以覆盖节目页近期列表之外的旧单集。它直接解析 `xiaoyuzhoufm.com` 官方页面内嵌数据，记录抓取时间和每集的：

- `playCount`：累计播放；
- `clapCount`：点赞或鼓掌；
- `favoriteCount`：收藏；
- `commentCount`：评论；
- 发布时间、时长、单集 ID 与规范链接。

把这些字段加入内部覆盖图。字段存在且值为 `0` 时保留为真实零值；字段缺失时标为“不可得”，不要以零代替。不要把当前访问者的 `isFavorited` 等布尔状态当成总量。播放与互动计数不是独立听众数、完播率或留存率，评论数还可能包含回复；不要扩大解释。脚本或官方页面结构失效时，逐一检查官方链接当前可见数据并说明缺口；不要改用第三方估算或虚构互动数据。

将数据视为带时间戳的累计快照，按以下规则解释：

1. 分开判断“触达”和“共鸣”：播放量主要反映触达；点赞率、收藏率、评论率分别提供满意度、留存参考价值和讨论意愿的线索，不能互相替代。
2. 先按相近发布时间、发布批次和上线天数建立可比组，再比较播放量及每百次播放的互动率。`每日播放`只能作为辅助，不要把发布一年的单集与发布三天的单集直接排序。
3. 低播放量下的互动率波动很大。极小样本默认按中性证据处理，不因一次点赞或收藏得到最高评价。
4. 把每集的年代、法域、法律机制、叙事入口、标题结构、是否连接当下等标签与表现相连。只有同一方向至少出现两次，或单集表现远高于可比组且有明确听众评论支持时，才把它视为方向信号。
5. 区分相关与因果。发布频率、节目订阅规模、外部热点、标题、时长和推广都可能影响表现；不要断言某个题材“导致”高播放。
6. 从表现较好的方向中抽象可复用结构，例如“具体人物或案件切入程序规则”，不要复制已经讲过的核心问题。表现偏弱的方向也不是禁区；若资料和主题价值足够，应说明将如何改变切口。

## 读取微信公众号对应文章表现

在用户明确授权后使用 Chrome 控制技能读取后台。保持只读，不发布、编辑、删除或导出内容，也不读取 cookies、local storage、密码或其他会话材料。优先接管用户已打开的“公众号”后台标签页；若没有可用登录会话，请用户先在 Chrome 中登录并打开后台。

从“内容管理”的全部发表记录或“数据分析”的内容分析进入逐篇数据，覆盖全部已发布单集的对应文章，不只读取首页近期列表。以期数、完整标题、文章规范链接和正文中的单集链接共同匹配；没有期数、集中补发、重发或一集对应多篇文章时，记录匹配依据，将无法唯一对应的文章标为“待确认”，不得为了凑齐数据强行归集。

为每篇已匹配文章记录后台读取时间、文章发表时间、标题、规范链接，以及当前界面明确标注的文章级指标。后台改版后必须以当前页面的实际标签和说明为准，不按数字的列位置猜字段，也不把账号首页的“昨日阅读”“总用户数”等账号级指标分摊到单篇文章。不要记录或输出后台 URL 中的 token 等会话信息。

将数据视为带时间戳的累计快照，并按以下规则解释：

1. 公众号阅读反映文章触达，不是播客播放或收听人数；分享、收藏、爱心赞、拇指赞和留言分别提供扩散、留存参考价值、轻互动和讨论意愿的线索，不互相替代。
2. 使用公众号文章的发表时间和上线天数建立可比组，不沿用播客单集的发布时间。集中补发旧稿、同日连发、推送位置、标题格式、账号关注规模和外部转发都可能显著影响表现。
3. 后台若同时提供阅读次数与阅读人数则分别保留。计算互动率时必须明确使用哪一项作为分母，并在可比组内保持一致；不同口径或不同累计窗口不得直接比较。
4. 低阅读量下的互动率按中性证据处理。只有同一方向至少出现两篇可比文章，或单篇显著高于可比组且有留言内容支持，才把它视为方向信号。
5. 默认只摘录与选题判断有关的聚合结论和代表性文章，不输出无关的账号级私有数据。留言内容只用于归纳主题反馈，不披露读者身份或其他个人信息。

## 合并跨平台反馈

先分别分析小宇宙和微信公众号，再合并为“往期听众反馈”证据；不得相加播放量与阅读量、跨平台计算统一互动率，或因绝对量级较大就让一个平台压过另一个平台。

- 两个平台的可比组都支持同一题材或叙事结构时，将其视为较强的跨平台信号。
- 两个平台方向不同时，说明这可能来自受众、载体、标题、分发或上线时点差异，分别保留结论，不取简单平均，也不把差异解释成内容质量的确定因果。
- 只有一个平台数据可得时，使用该平台证据并明确覆盖缺口，不因此机械扣分；两个平台都不可得或都不可比时，将“往期听众反馈”记为中性。
- 平台表现只用于选择可复用的切口与叙事结构。公众号文章高阅读或高互动不能证明相应音频选题必然更受欢迎。

## 建立候选池

先在内部形成多个候选题，再选一个最终题，不要看到第一个可用题就停止。候选题应覆盖不同年代、法域和法律机制，并同时包含常青题与具有当下连接点的题。

围绕以下节目母题寻找具体切口：

- 国家权力与个人权利如何彼此限制或失衡；
- 礼俗、道德与成文规则如何冲突、吸收或分离；
- 司法程序、证据制度和法律职业如何塑造正义；
- 一项制度如何在案件、人物或政治危机中被争夺、修补和重写；
- 东西方法律传统在相似问题上为何走向不同路径。

优先选择能由一个人物、一桩案件、一份法律文件或一个制度转折带入的题目。避免把宽泛的法学概念、纯时事评论、人物传记或政治立场本身当成选题；法律史问题必须是叙事主轴。

## 核对传播时点和资料基础

联网检索当前日期附近的法律事件、判决、纪念节点、影视或出版话题及公共讨论，为候选题寻找真实的传播入口。技术性法律问题优先使用法院、立法机关、档案馆、政府公报、大学出版社、同行评议论文和可靠学术机构等一手或权威来源。

- 不把搜索结果数量、单个平台帖子或主观印象写成“全网热议”。
- 不为追热点牺牲节目主题；时事只应是进入法律史的门，而不是节目全部内容。
- 不把尚未确认的判决、争议性传闻或错误周年日期作为传播钩子。
- 无法联网时，按常青传播价值选择，并明确未核验实时热度，不虚构趋势或互动数据。

同时做一次资料可行性检查：确认存在足以重建事实、制度背景、法理争议和后续影响的可靠资料。只有二手转述、资料高度单边或核心事实无法交叉验证的题目不得入选。

## 评分并选定一个题目

按 5 分制在内部评分，再应用权重：

| 维度 | 权重 | 判断重点 |
| --- | ---: | --- |
| 主题契合 | 25% | 是否真正属于东西方法律史及节目的核心冲突 |
| 垂类深度与可研究性 | 25% | 是否有一手材料、制度机制、学术争论和可验证因果链 |
| 相对历史单集的新颖度 | 15% | 是否在核心问题、法律机制、人物案件和论证结构上形成新增量 |
| 往期听众反馈 | 15% | 综合小宇宙与公众号各自可比组，是否支持至少一个触达或共鸣方向，同时避免重复核心问题 |
| 当前传播价值 | 10% | 是否有真实时点、具体钩子、认知反差和可准确概括的核心问题 |
| 节目组合平衡 | 10% | 是否改善中外、古今、个案与制度史、实体与程序的覆盖平衡 |

主题契合或垂类深度低于 4 分的候选题直接淘汰。不要用高传播分、历史高播放方向或公众号高阅读方向补偿法律史深度不足。两个平台都缺少可比证据，或平台方向冲突且无法解释时，将“往期听众反馈”记为 3 分中性值并说明原因；只有一个平台数据可得时可据其评分，但必须降低证据置信度，不要凭主观补分。分数相近时，优先选择兼具明确主角、关键法律文本、制度转折和多方立场的题目。

对最终选题再做一次去重检查：分别比较历史单集的核心问题、关键法律机制、中心人物或案件、主要史料与预期结论。仅更换国家、年代或人物，不足以构成新选题。可以延续旧题，但必须有新的核心问题，并在选题依据中说明承接与新增之处。

## 撰写标题与简介

标题使用完整单集格式：`NN 标题`，不添加“义正言辞”前缀。保持现有节目的克制风格，优先采用以下结构之一：

- 具体人物或案件：制度性问题；
- 熟悉话语或场景：它如何成为法律规则；
- 一个准确的问题：历史冲突或制度后果。

标题应让非法律专业听众看懂，同时保留一个可研究的法律史命题。不得标题党，不使用“震惊”“颠覆认知”等营销词，不把复杂争议伪装成已经确定的单一结论。

简介写成一个自然段，通常为 100 至 180 个汉字。用具体场景、反常识事实或清楚问题起笔，随后交代人物、案件、时间和制度线索，最后落到本期追问。简介要能独立用于播客平台和社交媒体，不写空泛的“带你了解”，不承诺研究无法支持的结论。

## 生成适合 Deep Research 的计划性研究提示词

产出一段可直接复制给 ChatGPT Deep Research 或其他研究型模型的完整中文提示词。把最终题目、简介、当前日期、研究截止日期、法域、时间范围和交付要求写实，不保留方括号变量或其他待补内容。

提示词必须把研究报告定位为后续正式节目文案的核心材料，**不是口播稿，也不要代写节目文案**。目标读者是不了解该专题、但需要据此写作的中文播客作者；报告必须先让读者理解问题和论证路线，再提供细节与来源。

### 先固定研究契约

不要把所有相关问题并列为同等重要的清单。提示词必须明确以下内容：

1. **一个中心问题**：整份报告最终只需回答一个可争辩、可由证据回答的法律史问题。若无法在不并列多个独立问题的情况下形成中心问题，应先缩小范围或建议拆题，不得用空泛的上位问题强行统一。
2. **一个待验证的初步命题**：用一至两句话说明目前最可能的解释，同时明确它只是工作假设，不得预设结论。
3. **三至五个子问题**：按“事实与制度起点 → 关键转折或机制 → 结果、限度与影响”的逻辑服务中心问题；每个子问题说明它为何必要。
4. **优先级与篇幅预算**：区分核心论证、必要背景和延伸材料。核心对象及其法律机制通常占正文至少一半；远因史、后续更新、跨法域比较和时事连接只有在直接解释中心判断的成因、机制、适用边界、反证或替代解释时才进入正文，否则放入附录或明确排除。
5. **范围边界**：写明研究的时间、法域、人物、案件、法律文本，以及不研究什么。避免把一个提示词扩张为数个彼此独立的研究项目。
6. **成功标准**：读者看完应能用一段话复述“发生了什么、法律为何如此运作、争议在哪里、最终能下什么有限结论”，并能追溯支撑这些判断的来源。

正文通常建议为 12,000 至 18,000 个中文字符，包括阅读导航、范围与方法、主体分析、综合结论和播客写作素材包，仅事实核查表和参考文献不计入；表格不得用于规避篇幅预算。题目需要不同长度时，在研究计划中说明理由；不要为满足字数堆积背景材料。

### 强制研究计划阶段

提示词要求模型在开始大规模检索前先提交一份可审阅的研究计划。若平台提供计划确认环节，先等待用户确认或修改再继续；若无法暂停，也必须先形成计划并据此执行。研究计划使用表格或紧凑列表，至少包括：

- 中心问题、工作假设及可能推翻它的证据；
- 每个子问题所需回答、优先证据类型、预期争议和对应报告章节；
- 一手资料与关键二手研究的查找路径；
- 最容易混淆的法域、时间、程序或概念；
- 明确排除项、资料缺口和停止继续扩张检索的条件；
- 计划中的报告目录及各部分篇幅比例。

计划不是搜索关键词清单。它必须显示各子问题如何共同回答中心问题；发现核心事实不成立、资料不足或范围失控时，应先调整计划并说明，而不是继续堆积旁支资料。

### 按证据问题执行研究

提示词要求按子问题组织检索和笔记，不按“找到什么写什么”组织报告：

1. 优先使用法律原文、判决书、官方档案、立法资料、当事人文书、同期报刊等一手材料，再用大学出版社著作、同行评议论文和可靠学术机构研究解释争议。
2. 区分历史事实、当事人主张、法院认定、规范内容、学者解释和报告推论；不得把它们合写成一个无来源的确定结论。
3. 对决定中心结论、存在争议或容易误传的事实进行独立交叉核验。单一权威一手材料已经直接控制该问题时，可说明其证据地位，不为满足形式上的“双源”要求拼凑低质量来源。
4. 记录相反证据、主要替代解释、证据局限及尚未解决的问题。工作假设被推翻时修改结论，不隐藏冲突。
5. 区分事件发生时的法律、后来修正的法律和研究截止日期的现行状态；涉及当前事件时，单列更新日期和历史类比失效之处。
6. 不编造文献、页码、引语、链接、对白、心理活动或戏剧细节。找不到可靠依据时明确写“未核实”，不以叙事完整为由填补史料空白。

### 按论证路线合成报告

提示词不得只给主题清单；必须指定以下报告结构：

1. **阅读导航**：用 600 至 1,000 字的清楚中文给出中心问题、核心结论、三至五步论证路线、最重要的限定和仍未解决的问题。读者只看这一节也应理解全篇。
2. **问题—结论矩阵**：逐项列出子问题、简短答案、关键证据、主要反证或限制和置信度。
3. **范围、概念与方法**：说明研究边界、核心术语、证据层级和报告不主张什么；只保留理解正文必需的方法说明。
4. **三至五章主体分析**：按因果、程序或时间推进，通常每个子问题对应一章；只有一个子问题确需拆分为两个不同机制或程序步骤时，全文最多六章。章首先用两三句话直接回答本章问题，再展开事实、法律机制、证据与争议，章末说明本章如何推进中心结论。
5. **综合结论**：明确回答中心问题，区分“证据可以支持”“仍有争议”“不能推出”三类结论；不得在结尾突然加入正文未分析的新材料。
6. **播客写作素材包**：主体分析完成后再附关键时间线、人物关系、核心概念、案件、法条和法律文件、可核实的关键场景、短引语及上下文、常见误解。叙事素材不得打断主体论证。
7. **事实核查表**：列出拟用于节目文案的关键主张、证据状态、直接来源、精确页码或章节、冲突来源和待确认事项。无页码材料改用条文、段落编号、章节、页面锚点或音视频时间戳，并明确标注“无页码”，不得猜测页码。
8. **分组注释书目**：区分一手资料和二手研究，写明每项资料支持哪个子问题、证据局限、作者、题名、机构或出版物、日期、页码或章节、稳定链接和访问日期。

不要在主体分析中提前插入节目提纲、开场方案或写作建议。需要这些材料时统一放入“播客写作素材包”，确保报告先完成研究论证，再服务节目转化。

### 保证可读性与可追溯性

提示词要求使用自然、准确的中文：

- 面向聪明但不熟悉该专题的读者，专业术语首次出现时用中文解释并附原文；不要连续使用未解释的英文判例术语或论文腔缩写。
- 段落先写判断，再写证据和限定；使用分级标题和必要表格，但不要把本应解释的因果关系全部压进密集表格。
- 每个实质性事实和引语使用紧邻引用；同一来源支持的一组连续事实可在段末合并引用，争议事实和直接引语必须单独引用。正文引用应可点击；参考文献还要提供完整书目信息和直接稳定链接，不得只留下平台内部引用编号。
- 引用转引材料时继续追溯原始出处；百科、媒体综述和搜索摘要只能作为线索，不能代替核心证据。
- 对译名、日期、数字、案号、裁判结果、程序姿态和引语逐项核对；给出证据强弱，不强行凑来源数量。

提示词结尾加入交付前自检：中心问题是否得到明确回答；各章是否都推进同一条论证；背景、比较和时事是否挤占核心对象；事实、法律与解释是否分层；关键结论是否可追溯；未核实事项是否显式保留；报告是否能被下游文稿技能直接提取为时间线、人物、概念、案件、法条和核查清单。任何一项不满足时先修订报告再交付。
